## 1. 영상이 실제로 말한 것

쇼츠 자체는 26초짜리 후킹 영상이고, 알맹이는 고정 댓글의 노션 문서에 있다. 자막 전문:

> 요즘 해외에서 굉장히 핫한 아저씨가 있어요. 바로 포니테일 아저씨예요. 특히 바이브 코딩을 할 때는 이걸 모르면 절대 안 됩니다. 제가 웹사이트를 만들어 봤는데 이렇게 그냥 시키면은 코드가 굉장히 길어져요. 근데 만약에 포니테일이 오픈 소스를 활용해서 만들면은 코드가 이렇게 달라져요. 근데 이거를 사용할 때 "기능은 유지하고 불필요한 코드는 줄여줘" 그러면은 코드가 짧아지고 읽기 쉬워지고 심지어 고장날 지점도 줄어들어요.

즉 "포니테일 아저씨"는 특정 인물 밈이 아니라 **`ponytail`이라는 오픈소스 에이전트 스킬**을 가리킨다. 로고 캐릭터(포니테일 묶은 시니어 개발자)에서 온 이름이다.

- 저장소: <https://github.com/DietrichGebert/ponytail> (MIT, 확인 시점 v4.8.4)
- 슬로건: *"He says nothing. He writes one line. It works."* — 게으른 시니어 개발자 모드

## 2. 핵심 메커니즘 — 결정 사다리(Decision Ladder)

코드를 쓰기 전에 아래 순서로 자문하고 **처음 걸리는 지점에서 멈춘다.**

```
1. 이게 존재해야 하나?      → 아니면 안 만듦 (YAGNI)
2. 코드베이스에 이미 있나?  → 재사용
3. 표준 라이브러리로 되나?  → 그거 씀
4. 네이티브 기능인가?       → 그거 씀
5. 이미 깔린 의존성인가?    → 그거 씀
6. 한 줄로 되나?            → 한 줄
7. 그제서야: 되는 최소한
```

체감 예시: "날짜 선택기 만들어줘" → 기본 에이전트는 flatpickr 설치 + 래퍼 컴포넌트 + 스타일시트 + 타임존 논의까지 간다. ponytail이 켜져 있으면 `<input type="date">` 한 줄로 끝낸다.

**중요한 단서 두 가지**

- *읽는 것에는 게으르지 않다.* 사다리는 문제를 이해한 뒤에 돌린다. 변경이 닿는 코드는 다 읽고 실제 흐름을 추적한 뒤 어느 칸에서 멈출지 정한다.
- *네 가지는 절대 잘라내지 않는다:* 신뢰 경계 검증, 데이터 손실 처리, 보안, 접근성.

## 3. 벤치마크 (저장소 README 기준)

FastAPI + React 레포에서 Haiku 4.5로 12개 기능 과제를 실제 Claude Code 세션으로 수행, 스킬 미적용 대비:

| 지표 | 변화 |
|---|---|
| 코드 라인 수 | **-54%** |
| 토큰 | -22% |
| 비용 | -20% |
| 완료 시간 | -27% |
| 안전성 | 100% 유지 |

**효과는 균등하지 않다.** 오버빌드 함정이 있는 작업에서 최대 94%까지 간다(날짜 선택기 404줄 → 23줄, 컬러 피커 287줄 → 23줄). 반대로 이미 최소한으로 짜인 코드에서는 거의 0이다. 즉 에이전트가 과잉 설계하기 쉬운 UI·유틸 작업에서 이득이 크고, 이미 압축된 로직에서는 별 차이가 없다.

## 4. 설치 (Claude Code)

프롬프트 창에 아래 두 줄을 **각각 따로** 입력한다. 한 번에 붙여넣으면 설치가 안 된다.

```
/plugin marketplace add DietrichGebert/ponytail
```

(엔터 후, 응답이 온 다음에)

```
/plugin install ponytail@ponytail
```

전제조건: `node`가 PATH에 있어야 한다. 플러그인이 작은 Node.js 라이프사이클 훅을 돌리기 때문이다. Node가 없어도 스킬 자체는 작동하지만 "항상 켜짐" 자동 활성화는 조용히 꺼진다. (nvm/Nix를 쓴다면 비대화형 셸 PATH에도 node가 잡혀야 한다.)

데스크톱 앱 Code 탭에서도 동일하다. 위 두 명령어를 입력하거나 `+` 버튼 → Plugins → Add plugin.

이 저장소에는 이미 [`.claude/settings.json`](../../../.claude/settings.json)에 프로젝트 스코프로 등록해 두었다 → §7 참고.

## 5. 커맨드

**모드 전환** (기본값 `full`)

| 커맨드 | 언제 쓰나 |
|---|---|
| `/ponytail` | 지금 모드가 뭔지 확인 |
| `/ponytail lite` | 살살 (프로덕션 코드 작업할 때) |
| `/ponytail full` | 기본값 |
| `/ponytail ultra` | 세게 (프로토타입, 실험 코드) |
| `/ponytail off` | 잠깐 끄기 |

**작업 커맨드**

| 커맨드 | 기능 |
|---|---|
| `/ponytail-review` | 지금 diff를 훑고 "이건 지워도 됨" 리스트를 뽑아줌 |
| `/ponytail-audit` | diff 말고 레포 전체를 감사 |
| `/ponytail-debt` | 미뤄둔 `ponytail:` 주석들을 모아 부채 원장으로 정리 |
| `/ponytail-gain` | 절감 효과 스코어보드 |
| `/ponytail-help` | 커맨드 요약 |

실무에서 가장 많이 쓰게 되는 건 `/ponytail-review`다. 커밋 전에 한 번 돌리면 "왜 이걸 만들었지" 싶은 코드가 잡힌다.

## 6. 추천 사용 패턴

- **하루차**: 설치만 하고 `full` 그대로 둔 채 평소처럼 쓴다. 코드가 눈에 띄게 짧아지는지 체감만 본다.
- **일주일차**: 커밋 전 `/ponytail-review`를 습관화한다. 여기서 나오는 삭제 리스트가 사실상 무료 코드 리뷰다.

**모드 선택 기준**

- 프로덕션 SaaS 코드 → `lite` 또는 `full`
- 내부 툴·프로토타입·1회성 스크립트 → `ultra`
- 아키텍처 설계 단계 → `off` (설계 논의를 "필요 없음"으로 잘라버릴 수 있음)

세션마다 바꾸기 귀찮으면 환경변수 `PONYTAIL_DEFAULT_MODE=lite`로 기본값을 고정하거나 `~/.config/ponytail/config.json`에 `defaultMode` 필드를 넣는다. 설정 파일은 필수가 아니다.

**제거할 때는 순서가 중요하다.** uninstall 스크립트 자체가 플러그인 파일이라 플러그인을 먼저 지우면 스크립트도 같이 사라진다.

```
node scripts/uninstall.js     # 먼저
/plugin remove ponytail       # 그 다음
```

## 7. 이 저장소에 적용한 것

`.claude/settings.json`에 프로젝트 스코프로 등록했다.

```json
{
  "extraKnownMarketplaces": {
    "ponytail": { "source": { "source": "github", "repo": "DietrichGebert/ponytail" } }
  },
  "enabledPlugins": { "ponytail@ponytail": true }
}
```

프로젝트 스코프 설정은 선언일 뿐 자동 설치가 아니다. 각자 로컬에서 이 폴더를 신뢰하면 Claude Code가 설치 여부를 묻고, 그 전까지는 "설치되지 않음"으로 뜬다. 물으면 수락하거나 `claude plugin install ponytail@ponytail`을 직접 돌리면 된다.

## 8. 설치 전 확인한 것 (공급망 점검)

서드파티 플러그인이 세션마다 Node 훅을 돌리므로 코드를 직접 확인했다.

- 훅 6개 + uninstall 스크립트 총 715줄을 검사 — **네트워크 호출 없음, `child_process`/`exec`/`spawn` 없음.** 로컬 상태 파일 읽기·쓰기와 프롬프트에 규칙을 주입하는 것이 전부다.
- 읽는 환경변수는 `PONYTAIL_*`, `XDG_CONFIG_HOME`, `APPDATA`, `CLAUDE_CONFIG_DIR`, 그리고 어떤 에이전트에서 도는지 판별하는 값들뿐이다.
- 훅 연결: `SessionStart`, `SubagentStart`, `UserPromptSubmit` 세 곳. 각 타임아웃 5초.
- 라이선스 MIT.

다만 이건 확인 시점(v4.8.4, 2026-08-06)의 스냅샷이다. 마켓플레이스 자동 업데이트가 켜지면 이후 커밋은 재검토 없이 들어온다는 점은 감안할 것.

## 9. 남은 한계

- 영상 파일 자체는 받지 못했다. 유튜브가 이 클라우드 IP를 봇으로 차단하고 tv 클라이언트 포맷에는 DRM이 걸려 있다. 자막·썸네일·메타데이터는 받아서 `assets/ttOkwofYJuw/`에 저장했다. 영상 원본이 필요하면 로컬 PC 세션에서 `yt-dlp`로 받으면 된다.
- 벤치마크 수치는 전부 저장소 저자가 제시한 자체 측정치다. 제3자 검증은 확인하지 못했다.
