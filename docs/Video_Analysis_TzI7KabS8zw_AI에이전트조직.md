## 🔍 "568명"의 정체 — 숫자를 해부하면

재현하려는 사람이 제일 먼저 알아야 할 사실입니다.

**1. 클로드코드에서 "에이전트 1명" = 마크다운 파일 1장입니다.**
`.claude/agents/<이름>.md` 파일 하나가 서브에이전트 한 명입니다. YAML 머리말(이름·설명·허용 도구·모델)과 시스템 프롬프트 본문으로 끝납니다. 즉 **568명 = md 파일 568개**입니다. 사람을 고용한 것도, 서버를 568대 띄운 것도 아닙니다.

**2. 568명이 동시에 일하지는 않습니다.**
API 동시 실행 한도와 토큰 비용 때문에 실제 병렬 실행은 보통 3~20개가 한계입니다. 화면의 "동시 진행 36개"가 오히려 진짜 가동 숫자에 가깝고, 568은 **정의된 정원(定員)**입니다.

**3. 대시보드 숫자는 대부분 파일 세기입니다.**
`에이전트 수 = agents 폴더의 .md 개수`, `진행 중 = status가 running인 JSON 개수`. 화면 자체는 HTML 한 장이고, 몇 초마다 상태 파일을 다시 읽어 숫자를 갈아 끼웁니다.

**→ 결론: 재현의 난이도는 "조직 규모"가 아니라 "에이전트가 자기 상태를 파일로 남기는 규율"에 있습니다.** 상태 파일만 있으면 568이든 5,680이든 화면에 찍는 건 똑같이 쉽습니다.

## 🏗️ 구성의 5개 층 (재현 레시피)

### Layer 1 — 에이전트 = 파일 한 장

```markdown
---
name: sermon-researcher
description: 설교 본문의 원어·주석·역사 배경을 조사할 때 사용. 본문 장절이 주어지면 자동 위임.
tools: Read, Grep, WebSearch, WebFetch
model: sonnet
---

너는 주석 리서처다. 히브리어/헬라어 원문과 주요 주석(Davies-Allison, France, Carson)을
대조해 3단 구조(원어 → 배경 → 적용 후보)로만 보고한다. 설교문은 쓰지 않는다.
```

핵심은 `description`입니다. **"~할 때 사용"이라는 트리거 문장**이 들어가야 상위 에이전트가 알아서 이 팀원에게 일을 넘깁니다. 여기가 부실하면 568명을 만들어도 아무도 호출되지 않습니다.

### Layer 2 — 부서 = 폴더 + 팀장

부서는 기능이 아니라 **폴더 구조와 호출 관계**입니다. 팀장 에이전트 하나가 팀원 3~5명을 부르고, CEO 에이전트가 팀장들을 부릅니다. 2단 계층이면 충분하고, 3단을 넘어가면 맥락이 소실되어 결과가 나빠집니다.

```
_agents/
  콘텐츠팀/
    팀장.md          ← 팀원을 호출하는 오케스트레이터
    블로그작가.md
    쇼츠대본.md
    썸네일.md
```

### Layer 3 — 상태 파일 = 대시보드의 연료 ★ 여기가 진짜 관문

에이전트가 작업을 시작할 때와 끝낼 때 **자기 상태를 JSON으로 덮어씁니다.**

```json
{
  "agent": "sermon-researcher",
  "dept": "설교실",
  "status": "running",
  "task": "마 6:9-13 주기도문 원어 대조",
  "started_at": "2026-09-17T14:02:11",
  "last_output": "docs/intelligence/research/마6_9-13.md"
}
```

이 한 파일이 없으면 대시보드는 영원히 못 만듭니다. 있으면 그 다음은 전부 쉽습니다.

### Layer 4 — 대시보드 = 폴링하는 HTML 한 장

```javascript
async function refresh() {
  const agents = await (await fetch('/api/agents')).json();
  document.getElementById('total').textContent  = agents.length;
  document.getElementById('active').textContent =
      agents.filter(a => a.status === 'running').length;
  // 부서별 그룹핑 → 카드 렌더링
}
setInterval(refresh, 3000);
```

서버는 `agents/` 폴더를 훑어 JSON 배열로 돌려주는 20줄짜리로 충분합니다.

### Layer 5 — 자율 사이클 = 스케줄러 + 메모리

윈도우 작업 스케줄러(또는 cron)로 N분마다 "사이클 1회"를 실행합니다. 한 사이클은 ① CEO가 오늘 할 일을 JSON으로 뽑고 ② 부서에 배분하고 ③ 각자 결과를 `memory.md`에 이어 붙이는 흐름입니다. **메모리가 누적되어야 "조직"이고, 없으면 매번 처음부터 시작하는 남남입니다.**

영상을 보고 처음부터 만들 필요가 없습니다. 아래는 실제로 확인한 내용입니다.

| 영상의 구성 요소 | 이 저장소에 이미 있는 것 | 상태 |
|---|---|---|
| 10개 부서 | `_company/_agents/` — browser, business, ceo, designer, developer, editor, instagram, researcher, secretary, writer, youtube (11개) | ✅ |
| 에이전트 페르소나 | `_agents/*/prompt.md` (예: `ceo/prompt.md` — JSON만 출력하도록 강제) | ✅ |
| 누적 메모리 | `_company/_agents/*/memory.md` (`ceo/memory.md` 150KB+) | ✅ |

| 이벤트 기반 협업 | `core/orchestrator/swarm_runner.py` — 매매 수익 발생 → 쇼츠 자동 제작 구독 | ✅ |
| 세션 로그 | `sessions/`, `_company/sessions/` — 15분 간격 타임스탬프 폴더 | ✅ |

| 무한 재시작 런처 | `alpha_master_launcher.py` — 프로세스 죽으면 자동 재시작 + 텔레그램 알림 | ✅ |

### 빠진 고리는 딱 하나입니다

**에이전트가 "지금 무슨 일을 하고 있는지"를 대시보드가 읽을 표준 상태 파일이 없습니다.**

`super_dashboard.html`은 현재 `/api/outputs`(생성된 영상 갤러리)만 봅니다. 즉 **결과물은 보여주는데 일하는 모습은 못 보여줍니다.** 영상의 그 화면 — 부서별로 에이전트가 실시간으로 깜빡이는 화면 — 은 정확히 이 한 조각이 빠져서 안 나오는 겁니다.

## 🚀 가장 빠른 길 (주말 2~3시간)

**1단계 — 규격 정하기 (30분)**
`_company/_agents/<이름>/status.json`을 Layer 3 형식으로 고정합니다. 새 인프라 필요 없음, 이미 있는 폴더에 파일 하나 더 놓는 겁니다.

**2단계 — 상태 쓰기 심기 (1시간)**
각 에이전트 실행 코드의 시작·종료 지점에 `status.json` 갱신 3줄을 넣습니다. 헬퍼 하나로 끝납니다.

```python
def mark(agent, dept, status, task=""):
    p = Path(f"_company/_agents/{agent}/status.json")
    p.write_text(json.dumps({
        "agent": agent, "dept": dept, "status": status, "task": task,
        "updated_at": datetime.now().isoformat()
    }, ensure_ascii=False), encoding="utf-8")
```

**3단계 — 대시보드에 패널 추가 (1시간)**
`super_dashboard.html`에 "조직도" 패널을 하나 더 만들고 `/api/agents`를 3초마다 폴링합니다. 서버는 `_company/_agents/*/status.json`을 모아 배열로 돌려주기만 하면 됩니다.

**4단계 — 숫자 카운터 (10분)**
상단에 `총 에이전트 수 = 폴더 개수`, `가동 중 = running 개수`, `누적 완료 = company_state.json의 tasksCompleted`. 영상과 같은 화면이 여기서 완성됩니다.

## ⚖️ 냉정한 평가 — 목사님 상황 기준

**568명은 만들 수 있습니다. 만들어야 하는지는 다른 문제입니다.**

- 에이전트 수는 **선형으로 비용과 관리 부담**을 늘립니다. 수익이 0원인 파이프에 에이전트 10명을 붙이면 딱 그만큼 적자입니다.
- 자비량 선교 기준으로 지금 필요한 건 3~5명입니다. 현재 진행 중인 일에 그대로 대응시키면:

| 에이전트 | 붙일 곳 | 우선순위 |
|---|---|---|
| 설교 리서처 | 주석 PDF + 원어 대조 → 설교문 초안 | ★★★ 매주 확실한 수요 |
| 시니어 건강글 작가 | 네이버·티스토리·워드프레스 (쿠팡파트너스 2주차) | ★★★ 수익 직결 |
| 중고등부 콘텐츠 | 예배 자료·영상 기획 | ★★☆ |
| 쇼츠 제작 | 대본·썸네일 (`src/luna-agent/luna_shorts_pipeline.py` 재활용 가능) | ★★☆ |
| 수익 리포터 | 쿠팡·애드센스·앱 지표 주간 집계 | ★☆☆ 파이프 안정화 후 |

- **역발상 하나:** 영상의 진짜 상품은 대시보드가 아니라 "이런 걸 만들었다"는 이야기입니다. 목사가 만든 AI 조직은 그 자체로 더 강한 후크입니다. 대시보드를 만든다면 **도구로도 쓰고 콘텐츠로도 쓰는** 걸 전제로 설계하세요. (조회수 56만은 기술이 아니라 서사가 만든 숫자입니다.)

## ⚠️ 주의 사항

- **API 비용**: 에이전트를 늘리기 전에 사이클 1회당 토큰 비용을 먼저 측정하세요. 자율 사이클은 잠자는 동안에도 돈을 씁니다.
- **시크릿**: `CLAUDE.md`에 기록된 대로 세션 로그가 auto-sync로 커밋됩니다(2026-06-22 OpenAI 키 유출 건). **`status.json`에 토큰·키를 절대 넣지 마세요.**
- 이 분석은 자막 없이 메타데이터 기반으로 작성했습니다. 영상 음성에 구체적 구현 설명이 있었다면 로컬 세션에서 자막을 뽑아 보완하세요.
