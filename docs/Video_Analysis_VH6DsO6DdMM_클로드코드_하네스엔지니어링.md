## 🧩 영상이 세우는 논지 구조

### 전제 — "같은 도구, 다른 결과"

바이브 코딩을 이름 붙인 Andrej Karpathy와, 클로드 코드를 만든 Anthropic은 **똑같은 도구로 완전히 다른 결과물**을 낸다.
차이는 모델이 아니라 사용법이다. 영상은 이 격차를 4개 층으로 나눠 채운다.

### 1층. 생성-검증 루프 (Generate–Verify Loop)

가장 근본이 되는 개념. LLM은 **"다 된 것처럼 보일 때" 멈춘다.** 그래서 돌려볼 수 있는 검사가 없으면
검증 루프의 주체가 사람이 되어버리고, 모든 실수가 사람이 눈치챌 때까지 대기한다.

에이전트가 스스로 읽을 수 있는 신호(테스트 결과, 빌드 종료코드, 린터 출력, 출력물 diff, 스크린샷 비교)를 주는 순간
루프가 닫힌다 — 짜고, 돌리고, 결과를 읽고, 통과할 때까지 반복. 사람은 그때부터 감시자가 아니라 검토자가 된다.

Anthropic 공식 문서는 이 게이트를 강도순으로 4단계로 정리한다:

| 강도 | 방법 | 성격 |
| --- | --- | --- |
| 약 | 프롬프트에 "테스트도 돌리고 통과할 때까지 고쳐라"를 포함 | 오늘 당장 가능 |
| 중 | `/goal` 조건 설정 — 매 턴 후 별도 평가자가 재확인 | 세션 전체에 걸림 |
| 강 | **Stop 훅** — 검사 스크립트가 통과할 때까지 턴 종료를 차단 | 결정론적 게이트 |
| 강 | **검증 서브에이전트** — 새 컨텍스트의 모델이 결과를 반박 시도 | 작성자≠채점자 |

핵심 원칙 하나: **주장하지 말고 증거를 내놓게 한다.** "동작합니다"가 아니라 실행한 명령과 그 출력을 남기게 한다.
내가 안 보고 있던 세션도 그래야 사후 검토가 가능하다.

### 2층. 65줄짜리 CLAUDE.md — 실패 모드 4가지를 정면으로 막기

영상이 "복붙 한 번이면 된다"고 소개한 파일. 배경을 정확히 짚어두면:
Karpathy가 2026-01-26 X 포스트에서 **LLM 코딩의 구체적 실패 모드**를 열거했고,
그걸 그대로 겨냥해 커뮤니티(Forrest Chang)가 만든 CLAUDE.md가 `multica-ai/andrej-karpathy-skills`로 공개됐다.
즉 **Karpathy 본인이 쓴 파일은 아니다** — "카파시 스킬"이라는 이름은 출처가 아니라 계보를 가리킨다.

네 규칙과, 각 규칙이 막으려는 실패 모드:

| # | 규칙 | 막으려는 실패 모드 |
| --- | --- | --- |
| 1 | **짜기 전에 생각한다** — 가정을 말로 꺼내고, 해석이 갈리면 선택지를 제시하고, 막히면 멈추고 묻는다 | 혼란을 숨긴 채 그럴듯하게 진행 |
| 2 | **단순함이 먼저다** — 요청받지 않은 기능·추상화·설정 가능성·불가능한 예외 처리 금지 | 과설계로 인한 전면 재작성 |
| 3 | **외과적 변경** — 주변 코드를 "개선"하지 않고, 안 망가진 걸 리팩터링하지 않고, 죽은 코드는 말만 하고 안 지운다 | diff 오염, 리뷰 불가능한 PR |
| 4 | **목표를 검증 가능한 형태로** — "검증 추가"를 "잘못된 입력 테스트를 쓰고 통과시켜라"로 번역 | 1층과 동일 — 검증 없는 완료 선언 |

파일 자체는 실행 코드가 아니라 **세션 시작 시 읽히는 행동 규범**이다. 영상이 인용한 "정확도 65% → 94%"는
해당 커뮤니티 자료의 자체 측정치이므로, 우리 저장소에서 그대로 재현될 수치로 받아들이지 말 것.

**트레이드오프도 원문에 명시돼 있다: 이 규칙들은 속도보다 신중함 쪽으로 기울어 있다.** 사소한 작업에는 과하다.

### 3층. Anthropic 공식 "정석 사용법"

영상이 5가지로 압축했다고 밝힌 부분. 공식 문서 기준으로 정리하면 모든 항목이 **"컨텍스트 창은 빨리 차고,
차오를수록 성능이 떨어진다"**는 단 하나의 제약에서 파생된다.

1. **검증 수단을 준다** (1층과 동일 — 문서에서도 첫 번째 항목)
2. **탐색 → 계획 → 구현 → 커밋** 순서를 분리한다. 플랜 모드로 탐색과 실행을 갈라놓아야 "엉뚱한 문제를 잘 푸는" 사태를 막는다.
   단, 한 문장으로 diff를 설명할 수 있는 작업이면 계획 단계는 건너뛴다(오버헤드).
3. **프롬프트에 구체적 맥락을 넣는다.** 파일을 지목하고, 제약을 말하고, 따라 할 기존 패턴을 가리킨다.
   "로그인 버그 고쳐" → "세션 타임아웃 후 로그인 실패, `src/auth/` 토큰 갱신 쪽을 봐라, 재현 테스트 먼저 쓰고 고쳐라".
4. **환경을 구성한다.** CLAUDE.md / 권한 설정 / CLI 도구 / MCP / **훅** / **스킬** / **서브에이전트** / 플러그인.
   여기서 결정적 구분: **CLAUDE.md는 권고이고, 훅은 결정론이다.** "매번 예외 없이" 일어나야 하는 일은 훅으로 내린다.
   가끔만 필요한 도메인 지식은 CLAUDE.md가 아니라 **스킬**로 빼서 매 대화 컨텍스트를 태우지 않게 한다.
5. **세션을 관리한다.** 어긋나면 즉시 교정하고, 무관한 작업 사이에는 `/clear`,
   **같은 문제로 두 번 교정했으면 컨텍스트가 오염된 것이니 새 세션에서 더 나은 프롬프트로 다시 시작한다.**

문서가 명시한 안티패턴 5종 — 이건 그대로 체크리스트로 쓸 만하다:

- **잡탕 세션**: 무관한 작업을 오가며 컨텍스트를 쓰레기로 채움 → `/clear`
- **반복 교정**: 실패한 접근들이 컨텍스트에 쌓임 → 2회 실패 후 새 세션
- **과대 CLAUDE.md**: 길어지면 진짜 규칙이 노이즈에 묻혀 무시됨 → 가차없이 쳐내고, 지킬 필요가 있는 건 훅으로
- **믿고 안 넘겨보기**: 그럴듯하지만 엣지 케이스가 없는 구현 → 검증 못 하면 배포도 안 함
- **무한 탐색**: 범위 없는 "조사해봐"로 수백 파일 읽음 → 범위를 좁히거나 서브에이전트에 위임

### 4층. 하네스 엔지니어링 — 영상의 최종 주장

> **에이전트가 실수했을 때, 그 실수가 다시 일어나지 않도록 모델 주변의 환경·구조·도구를 설계하는 것.**

영상은 발표자 본인의 매출 나는 서비스(edgelink)에 "겹겹이" 둘러놓은 하네스를 실화면으로 보여주는 방식으로 이걸 논증한다.
프롬프트 잘 쓰기는 1회성이지만, 하네스는 **자산으로 남는다** — 한 번 만들어두면 다음 세션, 다음 사람에게도 계속 작동한다.

영상의 마무리 문장: **"바이브 코딩으로 시작하되, 하네스 엔지니어링으로 운영하라."**

## 🏗️ 이 저장소(`nowhere78/home`)에 실제로 적용한 것

영상 내용을 문서로만 남기지 않고, 이 저장소에 실제 하네스 3겹을 설치했다.
설계 기준은 위 안티패턴 중 **"과대 CLAUDE.md"** — 65줄을 CLAUDE.md에 통째로 복붙하지 않고 계층을 나눴다.

### 1겹 — 결정론 게이트: 시크릿 차단 훅 (가장 강한 층)

`.claude/hooks/check-secrets.sh` + `.claude/settings.json` (PreToolUse / Bash)

이 저장소에는 **실제 사고 이력이 있다.** CLAUDE.md에 기록된 2026-06-22, 에이전트 세션 로그
(`*/.system_generated/logs/transcript.jsonl`)에 OpenAI API 키가 평문으로 들어간 채 auto-sync로 커밋되어
GitHub push protection에 걸린 건. 지금까지 이건 CLAUDE.md의 "주의할 것" 한 줄, 즉 **권고**로만 남아 있었다.
하네스 엔지니어링의 정의 그대로 — 실수가 있었으면 그게 다시 못 일어나게 환경을 바꾼다.

동작:
- `git commit` → 스테이징된 diff의 **추가된 줄만** 검사
- `git push` → 아직 origin에 없는 커밋들의 diff를 검사
- Anthropic / OpenAI / GitHub PAT / Google API / Slack / AWS 액세스 키 / PEM 개인키 패턴 매칭
- 걸리면 **exit 2 → Bash 실행 자체를 차단**하고, 마스킹된 근거를 에이전트에게 되돌려준다
- 우회를 명시적으로 금지하고 사용자 확인을 요구하는 문구 포함

검증 (증거):

| 케이스 | 기대 | 결과 |
| --- | --- | --- |
| git 아닌 명령(`ls -la`) | 통과 | exit 0 ✅ |
| 시크릿 없는 스테이징 + commit | 통과 | exit 0 ✅ |
| `sk-proj-…` 스테이징 + commit | 차단 | exit 2, 마스킹 출력 ✅ |
| PEM 개인키 헤더(`-----BEGIN … PRIVATE KEY-----`) + commit | 차단 | exit 2 ✅ |
| **훅 스크립트 자신의 커밋** | 통과 | exit 0 ✅ (자기 참조 오탐 제외 처리) |

### 2겹 — 온디맨드 규범: 코딩 하네스 스킬

`.claude/skills/coding-harness/SKILL.md`

Karpathy 계열 4규칙을 **이 저장소 상황에 맞게 번역**해서 스킬로 넣었다(원문 복붙이 아니라 적응).
스킬이라 코드 작업을 할 때만 로드되고, 설교문·말씀공부 페이퍼 작업 세션의 컨텍스트는 태우지 않는다.

이 저장소에 맞춰 추가한 부분:
- **이 저장소에는 통합 테스트 스위트가 없다.** 그래서 "검증 수단"의 최소 기준을 현실적으로 못 박았다 —
  실제 실행 로그 / `python3 -m py_compile` 통과 / `scratch/`에 재현 스크립트를 만들어 수정 전 실패→후 통과 증명, 셋 중 하나.
- 최상위에 UUID 폴더가 100개 넘게 있어 광범위 탐색이 컨텍스트를 태운다 → 탐색은 `Explore` 서브에이전트에 위임하라는 규칙 명시.
- 시크릿 훅에 걸렸을 때 우회하지 말라는 규칙.

### 3겹 — 상시 포인터: CLAUDE.md 최소 추가

CLAUDE.md에는 **8줄짜리 포인터만** 추가했다(59줄 → 유지 수준). 규범 본문은 스킬에, 강제는 훅에 있으므로
CLAUDE.md가 할 일은 "그런 게 있다"를 알리는 것뿐이다. 이게 공식 문서가 권하는 계층 분리다.

### 적용하지 않은 것 (의도적)

- **Stop 훅으로 테스트 강제**: 이 저장소에 돌릴 테스트 스위트가 없다. 없는 명령을 게이트로 걸면 모든 턴이 막힌다.
  테스트가 생기면 그때 추가하는 게 맞다.
- **65줄 원문 그대로 복붙**: 공식 문서가 경고하는 "과대 CLAUDE.md"를 그대로 만드는 일. 스킬로 분리했다.
- **"정확도 65→94%" 수치 인용**: 커뮤니티 자체 측정치라 우리 환경 기대치로 쓰기 어렵다. 규칙만 가져왔다.

## 💡 알파에이전트 프로젝트로의 확장 포인트

이 저장소의 자율 에이전트 루프(`_company/_agents/*/memory.md`, `alpha_master_launcher.py` 등)에 그대로 옮길 수 있는 것:

1. **에이전트마다 "검증 조건"을 goal.md에 명문화한다.** 지금 `_agents/*/goal.md`는 목표는 있지만
   "무엇을 통과해야 이 사이클이 성공인가"가 없다. 이게 없으면 에이전트는 "그럴듯할 때" 멈춘다.
2. **auto-sync 파이프라인 앞에 훅을 세운다.** 이번에 만든 시크릿 훅이 첫 사례다.
   같은 자리에 "메모리 파일이 비정상적으로 축소됐는지"(덮어쓰기 사고 방지) 검사도 붙일 수 있다.
3. **작성자와 검토자를 분리한다.** 한 에이전트가 만든 산출물을 같은 에이전트가 평가하지 않게,
   fresh context 검토 에이전트를 한 겹 둔다 — 공식 문서의 Writer/Reviewer 패턴.
